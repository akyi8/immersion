# Immersion

Immersion is a desktop app for worldbuilding, writing fiction, and tabletop roleplaying: writing a game, running or playing in a campaign at a real table, and, later, playing solo. A world is an ordinary folder of markdown files, so everything Immersion shows can also be opened in Obsidian, VS Code, or any text editor, and synced with Git.

Immersion is in active development. The World, Story, and Boards modules work today. The Game module holds a tabletop game's rules, and the Table module keeps a campaign's sessions, rumors, rulebooks, handouts, dice, and cards. Play, which will run solo roleplaying sessions with an AI narrator, and the Character module are still being designed.

## What it does

### The library and the Worlds page

A library is one folder that holds a writer's worlds. The app asks where the library lives on first run, finds every world in it up to six folders deep, and lists them on the Worlds page with their cover pictures. Any folder of writing becomes a world when it gains a `world.md`, and the app can create a new world with starter categories for people, places, factions, and history. A world not in use can be archived, which moves it below the others under an Archived heading and changes nothing else about it.

When the library is a Git repository, Immersion keeps it in sync. It commits and syncs an open world every five minutes, three minutes after typing stops, whenever the app comes back to the front, and when the world closes. The header shows how many files are waiting to go out and how many are waiting to come in, and a button syncs at once.

### World

The World module is the wiki. Every entry is a markdown file, and any name that matches another entry becomes a link. Linked entries open side by side as sliding panes, and a sidebar gathers the people and places around the open entry. The World home page opens with a band of faces: every entry with a picture, people first, with the ones opened most recently at the front.

Each entry can carry a picture. The writer frames the picture by dragging and zooming it, and the picture file itself is never changed. People show their picture as a portrait, and places, factions, and other entries show theirs as a banner across the top of the entry, with the name over it. Any entry can switch between the two.

The app has two views, chosen by one switch in the header that shows in every module. Narrator view shows everything. Protagonist view hides passages marked as the narrator's secrets, so the screen can be shown to players without giving anything away. A wiki entry opened beside a chapter, a board, a rule, or a session follows the same switch.

### Story

The Story module holds the writing, sorted into three places: the drawer for ideas, the desk for work in progress, and the shelf for finished work. A piece of writing is either a note, which is a single file, or a manuscript, which is a folder of chapters with a title page. Title pages carry the subtitle, series, author, and copyright, and can draw the author from a shared author profile.

The writing view is a live markdown editor. Markdown marks stay hidden until the cursor reaches them, names from the wiki link as they are typed, and a selection bar offers bold, italic, underline, and making a new wiki entry from a name. Bold, italic, and underline work on the words and never on the marks: a selection that is partly bold becomes wholly bold with one pair of marks, pressing the key again clears it, and taking the bold off the middle of a phrase leaves both ends bold. With nothing selected, Ctrl or Cmd B puts the cursor between a fresh pair of marks, ready to type, and pressing it again steps out of the bold. Each chapter's beat, its plan in a sentence or two, folds above the prose, and a Beats panel shows the chapter's beats on every thread beside the writing. Drafting mode hides everything but the page.

The vault keeps private stories encrypted. One passphrase unlocks every world's vault. The passphrase becomes a key through Argon2id, the stories are encrypted with AES-256-GCM, and a computer can remember the key in its own keychain. Each story is sealed to its own file name and to its world's id, so one story's file copied over another's, or moved into another world, refuses to open. A remembered key opens the vault on that computer without the passphrase, for anyone using it as the writer. Locking by hand, from the Lock button or with Ctrl or Cmd, Shift, L, sets the remembered key aside until the passphrase is typed again. The vault does not lock while a story in it cannot be saved, and it says so. Real World is a journal world that the app creates for the writer, and its stories live in the vault.

### Boards

The Boards module draws the plan of the world as grids, with time or order along one side and threads along the other:

- **The timeline** sets every dated wiki entry in order, with eras drawn as bands beside the events inside them.
- **A manuscript's board** has one card per chapter, with its beat on each thread.
- **A series board** has one card per book, so a series can be planned before its books are written.

A board can carry a story structure, such as Kishōtenketsu, the Story Circle, or four acts. The board then groups its cards by the structure's parts, and guidance for each structure is a click away. Cards can be dragged, moved by name from a right-click menu, and edited in place.

### Game

The Game module holds a tabletop game's rules as separate elements, one file each. An aspect, such as a piece of gear, is edited as a form with its own fields, or in a sheet with every aspect of its kind, and a rule is written in the same editor as a chapter. A game is built on an engine, whose core elements appear in every game built on it. Each world adds elements of its own and brings new kinds of element if it needs them. A world's files can also set aside a core element or reskin it, giving it a new name and flavor while keeping its mechanics, and the app reads both, though it no longer offers them on an aspect's page. The module is off until it is turned on in Settings. A world with no game starts one from the Game module's own page, which offers each engine the library's other worlds are built on. Choosing one names the engine in the world's `world.md` and lays the world's book out over the engine's: the same divisions, each with the engine's sections, and the engine's front and back matter. The core rules are in place at once, and the world adds its own from there.

A kind's page lists every element of that kind, and a switch at its top shows the same elements as a sheet. In the sheet each element is a row and each of the kind's fields is a column, with the name first and the flavor last, and every cell is typed in place and saved as its form saves. Tab moves across, Alt with an up or down arrow moves between rows, and Enter moves down from a one-line cell. A line at the foot adds an element by its name. A control under a name opens that element's form, which is unchanged. The sheet is wide, so it reads best with its page in full screen.

A game's rulebook is kept as a book. A world's book follows the base game's: the base game's divisions and sections stand in the base game's order and under its names, anything added to the base game shows in every world built on it, and a world's own divisions and sections are laid over that, each at the number it holds in the world's list. In a world's book a core section cannot be dragged, because its place is set in the base game. An element's kind and its tags are one set of labels, and a `labels.md` in the engine or the world says what a label means, such as how a name with that label links. A division can list its elements by any label, a kind or a tag, so a Keywords list can gather everything tagged `keyword`. A right click on an element's row opens its menu. A core element is archived from the base game's book, and a world's book offers to go there. The Game sidebar shows it as a tree: the book's title page, its front matter, its divisions, the rule sections in each division, then its back matter. A section's name opens its page, where its rules are written. The + beside the book's name adds a section at the top of the book, after the front matter, such as an introduction. A core section carries the Core mark, as a core rule does. The twist beside a section shows its rules in the tree, to drag one into a new order or into another section. A section is where a game is written. It opens as one continuous page that reads the way the book prints: its introduction, then every rule under its heading in book order, each written in place in the same editor as a chapter. A rule's name is renamed by typing over it, a control beside the name opens the rule alone, and + New rule at the foot adds one. A core rule carries one small mark, Core, which says that an edit there changes every game built on the engine. A world never changes a core rule's text. It adds its examples and clarifications after the rule, under the words In and the world's name, and a core rule with nothing added shows a small control to add it. A rule's tags are kept under the ⋯ in its page's corner. Any page can carry a header picture, and a world can give a core rule a picture of its own. A division can list every element of some kinds instead, so the aspects print as lists. In a world, the book on screen is the world's. The base game's own book, for its title page and the order of its divisions, opens from a link at the foot of the tree, with a clear way back. A world's game can also have expansions, each a folder of its own that adds gear, vendors, and other elements of its own without changing anything in the world, so a table can play with any mix of the expansions it owns. An element can move between the world and its expansions. The title page is drawn from fields, as a manuscript's is: the title, a line under it, the author from an author profile, and the copyright line. A book prints its title page, then its front matter, then its divisions, so an introduction is a page of the front matter.

A rule, a section, or any other element is archived from the ⋯ in the corner of its page or from a right click on its row in the tree. Archiving takes it out of every section, division, and book that listed it and moves its file into the game's `archive` folder, with a note of where it stood. A core element in a world's game is set aside instead, since every world shares it.

### Table

The Table module holds campaigns played at a real table, for the game master who runs one and for a player who plays in one. A campaign holds adventures, and an adventure holds sessions. The sidebar shows them as a tree.

- **A session has two sides.** The log is what happened, and the plan is what the game master prepared. For a campaign you run, a session opens with its plan and its log side by side. For a campaign you play in, a session is its log. Plans show only in Narrator view.
- **One menu for each thing.** A campaign, an adventure, a session, a rulebook, and a handout each have one menu, with Rename and Archive. It opens from a right click on the thing's row, from the button that shows on the row under the pointer, and from the ⋯ in the corner of its page. Renaming is typing over the title on the page, and Rename in the menu puts the cursor there. Archiving moves the files into an `archive` folder and deletes nothing.
- **Protagonist view** puts session plans and narrator-only text away and shows sessions and text handouts for reading, so the screen can be shown to players.
- **A session's facts** sit under its name: the day it was played, the date in the game, and who was at the table. A new session starts with the last session's date in the game and its table, and its log opens with where the last session ended.
- **Names link** in a session as they do in a chapter, and a selected name can be made into a wiki entry.
- **Rumors.** Selected text in a session or a wiki entry can be marked as a rumor: something suspected and not known. A campaign's Rumors page lists every rumor in its sessions and in the wiki, and marks each one confirmed or false. Text with no mark is known to everyone, and narrator-only text is the game master's secret.
- **Dice and cards.** A tray at the foot of the Table sidebar holds dice and cards. The dice are drawn as their shapes: a click adds one die of that shape to the roll, a right click takes one away, and Roll throws them. A roll can also be typed the way players say it, such as 2d6+3. The dice tumble across the screen in the world's own color and land where they fall, which Settings, under This computer, turns off. A campaign that uses the world's own game shows the eight-sided die alone, and its roll counts trouble against an edge, with the dice in trouble marked. A roll or a drawn card can be written into the session log you were last in, with what it was for. The tray stays on screen in full screen. A poker deck and the tarot come with the app, any other deck is a file that lists its cards, and a campaign remembers what has been drawn until the cards are shuffled back.
- **Rulebooks.** A campaign's page adds a rulebook by copying a PDF you choose into the campaign's `rules` folder, and any PDF put in that folder by hand shows too. A rulebook opens from the sidebar in a pane beside the session. In a pane it shows one page, sized so the whole page and its controls stay on screen, and Larger fills the pane's width instead. In full screen it shows two facing pages with the book's contents list open beside them. The arrow keys and the mouse wheel turn pages, and a book opens on the page it was left on. Typing over a book's name renames its file. The sidebar lists a campaign's rulebooks under their own heading.
- **Handouts.** What the game master hands the table is kept in a campaign's `handouts` folder: PDFs and pictures, such as maps, letters, and portraits, and pages of text, such as a message pasted in from a chat. The sidebar lists a campaign's rulebooks and its handouts under their own headings, with the links that add one at the foot of each list. A text handout is written like any other page, and names in it link. The pane's window button opens a handout or a rulebook in a window of its own, where it shows alone, to sit on a second screen or be shared on a call. A text handout shown that way leaves out narrator-only text.
- **A campaign's page** holds its name, whether you run it or play in it, which game it uses, and links the table shares, such as a spreadsheet of characters, each of which opens in the computer's browser.

### Across the app

- **Quick finder.** Cmd K on a Mac, and Ctrl K elsewhere, finds any entry, manuscript, chapter, board, campaign, session, rulebook, handout, game rule, section, or element in the open world, and a few actions. A wiki entry found from Story, Boards, Game, or Table opens beside what is already open there, so looking someone up in the middle of a session never loses the place.
- **Saving.** Everything typed saves on its own a moment after typing stops, and at once when the writer turns to another program, leaves a world, or closes the window. A save waits until the disk holds the words before it replaces the file, so a power cut never leaves an empty page. A file that came with Windows line endings keeps them. While Git joins another computer's changes into the files, saves wait a moment, so a save and a sync never write the same file at once.
- **Edits from outside.** A file changed by another program while it is open in Immersion, such as by a Git pull or an assistant working in the same folder, shows the change at once. When the writer has unsaved typing in the same file, edits to different paragraphs are joined, and the writer is asked to choose only when both changed the same lines.
- **How a page is shown.** Every open page has a view button in its corner, beside full screen. It makes the page's text smaller, and holds everything about the page's picture: whether it is hidden or shows as a portrait, a banner, or behind the page, and changing, framing, and removing it. A hidden picture and the text size are remembered for each page on each computer. The picture and its shape are kept with the page.
- **Escape closes a page.** Escape closes the page being written in, after saving everything, and with no page in use it closes the last one. A menu, a dialog, Settings, the finder, or full screen takes Escape first when one is open.
- **A page as a card.** An entry's picture can lie behind the page. The picture then stands as a tall strip down the page's left side, clear at the edge and fading quickly toward the text. The entry's name runs up the left edge over the picture, with its category above it, and the entry's first sentence is set across the top. The name and the picture share one side, which leaves the rest of the page to the text. The framing dialog shows the picture in that shape with that fade. The card stays with its column of text on a wide screen. On the spine one word of the name is set large, with the rest of the name small beside it. A click on any of the small words makes that word the large one, a click with Shift held makes it large as well, so two or more words can stand large, and the entry remembers the choice. Until a word is chosen the app guesses: a nickname in quotes, and otherwise the first word that is not a title or a joining word. A The, A, or An stays with the word after it. One setting under This world shows every entry's picture the same way, as a portrait, a banner, or behind the page, and an entry can still choose for itself.
- **Nothing closes over unsaved writing.** Before the window closes or a world gives way to the Worlds page, everything open is saved, and a clash still waiting for an answer is settled in the writer's favor. If a page cannot be saved, the window or the world stays open and says so, and closing anyway is a choice. A page that has closed never tries its save again, so its text cannot land in the world opened next.
- **A kind's sheet.** A kind's page can show its elements as a sheet, one row for each, typed in place. Each row has the element's name, its tags as one line with commas between, each of the kind's fields, and its text. Every other row sits on a slightly different ground, so one row can be followed across a wide sheet.
- **Hover cards.** Resting the pointer on a linked name for half a second shows a small card saying who or what it is: the name up the spine at one size, its category, a one-line summary, its other names, and its picture behind when it has one. A game term's card gives the term's kind, its summary, where its full rule is written, and its tags. The summary is `summary:` in the file's header when there is one. A keyword without one shows its reminder, and anything else shows its first sentence. No card shows while typing, and a key, a click, or a scroll puts it away. A click on the name still opens its page.
- **Icons, on trial.** Small icons stand beside the names in the World sidebar, on the World home page, and in the Game module's tree and lists. An icon has no color of its own: it wears the world's second color, so it follows each world's colors and stands apart from the name beside it, and the open row's icon takes the world's accent. Every wiki category and game label has one icon, and common names such as People, Places, Gear, and Keyword start with one. "Icon…" in a category's menu, in an entry's menu, or on a kind's page opens a picker with a search over about four thousand icons. An entry can carry an icon of its own in place of its category's. Settings, under Look, has an Icons switch that turns them all off. The icons are from game-icons.net, by Lorc, Delapouite, and other contributors, under the Creative Commons Attribution 3.0 license.
- **A page in a window of its own.** "Open in a new window" moves a page out of the main window, to sit on a second screen or be shared on a call. In every module the page is saved first and then closes in the main window, so it is never open in two places.
- **Links leave the app.** A link in a page opens in the computer's browser and never inside the app's own window. Rendered pages cannot hold forms or styles of their own.
- **A record of errors.** Immersion keeps the last sixty errors on this computer, including a letter key that changed nothing in a page. The record names a page by its number and never by its title or its words, since the page may be a private story. It also notes when the keyboard leaves a field in the middle of typing with no click to explain it, when the row of pages moves on its own, and when the spelling dictionary cannot be read. Settings, under Files, shows the record and copies or clears it. It never leaves the computer on its own.
- **Quiet while typing.** While you type, the page falls back in layers around the sentence being written. The rest of its paragraph loses a fifth of its strength, the other paragraphs lose nearly half, the other open pages lose three quarters, and the header, the sidebar, and the page's buttons all but go. The names and terms marked in the text being typed in go plain, and take their color back afterward. Pictures step back as well, both a page's own and the one that belongs to the Radiance room. It steps back a second after the typing starts and returns a second after the pointer moves, so a pause or a glance with the mouse does not make it flash out and in. Moving through the text with the arrow keys keeps the quiet, as typing does. Settings, under Writing and play, turns this off.
- **Spelling.** A misspelled word is set a little greyer and nothing else, with no underline. A word is looked up after the typing pauses, and the word the cursor is in is left alone. A right click on a greyed word offers what it might have been and adds it to your own dictionary, which is kept in the library's `immersion.md` and so follows you to every computer. A world's names and a game's terms are never marked, nor are words in capitals, words beside a digit, or the parts of an address. The dictionary is American English, and the same right click switches the open world to British spelling, which its `world.md` remembers as `spelling: british`. A world written in two languages can accept Spanish as well, from the same right click, which its `world.md` remembers as `spelling_also: spanish`. A word is then well spelled if either language has it, and a word missing its accent offers the accented word first, so pequena offers pequeña. Settings, under Writing and play, turns spelling off for this computer. The checker is nspell, with the dictionary-en word lists for English and dictionary-es-mx, the Mexican Spanish list from LibreOffice, for Spanish.
- **Names in a game's text.** A game's text links names as they are typed, the way a chapter does. The world's people and places are marked as names, and the game's own terms are set in small capitals in a second color. An aspect is the name of an ability, so it links where it is written with its capitals, and a one-word aspect that opens a sentence stays plain unless it is bold or italic. A mechanic, which is an element tagged `keyword`, is a concept, so it links however it is written: "burned" links the keyword Burned. Every name links in its plural too. Where a word is both a game term and a name from the wiki, it is the game term in game text. The names of divisions, sections, and rules never link. A click on a name opens its page beside the one being read. The front matter and back matter link nothing.
- **A page's menu.** What can be done to a page, such as renaming, moving, or archiving it, is behind the ⋯ in the page's corner, beside the view button, full screen, and close. A right click on the page's row in a sidebar opens the same menu.
- **Renaming.** A page is renamed by typing over its title: a wiki entry, a note, a manuscript, a session, a campaign, a rulebook, a handout, a board, a rule, a rule section, a division. Enter or leaving the title takes the new name, and Escape puts the old one back. Rename in any menu, the page's own or its row's in a sidebar, opens the page and puts the cursor in the title. A page with no title to type over asks in a small form instead: a wiki entry shown as a card, a manuscript's title page, a chapter inside a one-file manuscript, a wiki category, and an adventure. A renamed wiki entry keeps its old name as another name, so nothing that mentions it comes unlinked. A chapter that is a file of its own, and a game element, rename the same way.
- **Archiving.** Whatever the app can make, it can archive, from the ⋯ in the page's corner or the menu on its row: an entry, a category, a note, a manuscript, a chapter, a campaign, an adventure, a session, a rulebook, a handout, a rule, a section, an element. Archiving moves files into an `archive` folder and deletes nothing. A chapter inside a manuscript kept as one file is cut out of that file and saved as a file of its own in the archive.
- **Scroll bars.** Scroll bars are thin and have no track, and a bar's thumb shows only while the pointer is over the thing that scrolls.
- **An entry's facts.** An entry's other names sit under its name, its date under those, and under both the small buttons that add a name or a date. The file's own header is never shown in the app, and nothing in it has to be edited by hand there. Other names written as a bold line in the text show in that row and are hidden from the text. A rule drawn straight under an entry's title, before any text, is not shown.
- **A file moved elsewhere closes its page.** When a sync or another program moves or archives a file that is open here, its page closes and a short line at the foot of the window says why. A page holding typing that is not saved yet stays, and its words are saved at the old place.
- **Menus and forms from the keyboard.** A menu opened from the keyboard opens under the row it belongs to, Home and End reach its first and last choice, and Escape or Tab closes it and hands the keyboard back to where it was. A form keeps the keyboard inside it while it is open, hands it back on closing, and stays open while its work is under way. The forms take this behavior from Bits UI's Dialog, and their look is the app's own.
- **Back and forward.** The header's arrows, Cmd with a bracket on a Mac, Alt with an arrow elsewhere, and a mouse's side buttons move through everything looked at. The brackets mean Back and Forward inside the text as well, so they no longer indent a line there.
- **Settings.** A cog at the right end of the header opens Settings, and the world's menu and the finder open them too. Settings are one page with five groups down its left side, named for what a setting is for: Look, Theme, Writing and play, Modules, and Files. Theme holds the open world's colors and fonts. While it is open the page stands to one side, so the world's pages show the theme as it is chosen, and nothing is kept until Save the theme. Each setting has a short name, one sentence, and a small tag saying where the choice applies: this world, all worlds, or this computer. Every setting is changed where it sits, with a switch, a choice, or a small form, and a box at the top finds a setting by any word in it.
- **One look for each idea.** A choice between two or three things is drawn one way everywhere, as a soft track with the chosen part raised. A page's title is one size when the page stands alone and a smaller one when two or more pages share the window. Every sidebar row is the same height. The second color marks labels and quiet actions only, and running text that steps back is a warm grey.
- **Layouts.** Settings, under Look, choose how the app is laid out: Classic, ruled with fine lines. Soft, with space instead of lines and rounded paper on a desk. Radiance, which is Soft with a picture that belongs to the room. In Radiance the picture stands down the right edge of the window. It is whole at the edge and fades toward the pages into their own ground, black on the dark side and white on the light, and the paper runs under the whole picture, so no edge of the work area crosses it. The last page keeps its text and its corner buttons out of the picture's whole half. A page's picture is framed in the room the way that page frames it for Behind, from Frame and place the picture in the page's Aa menu. The world's own picture is framed from Settings, under Look, with Room picture. It is the world's picture, and while a page that has a picture of its own is the one in use, the room shows that page's picture instead. A page's own picture then shows in the room and not on the page. A narrow window puts the picture away.
- **Themes.** Each world has its own colors and fonts, chosen in Settings, under Theme. Each writer chooses light or dark, a layout, a board font, and a zoom level in Settings, under Look.
- **Modules.** Settings show or hide each module in the header, and the + after the last module in the header opens that list. World, Boards, and Story are on from the start, and Character, Play, Game, and Table wait until they are turned on. A click on the module already open closes its pages and shows its home.
- **Updates.** The app checks for a new release when it starts and every six hours, and offers to install it.

## What a world looks like

A world is any folder that contains a `world.md`:

```
harrowgate/
  world.md          the world's name, tagline, and folders
  world.jpg         the cover picture
  wiki/             one markdown file per entry, in category folders
    people/
      wren-okafor.md
      wren-okafor.jpg
    places/
  stories/          the desk: work in progress
    ideas/          the drawer
    finished/       the shelf
  table/            campaigns, each with its adventures and sessions
  game/             the world's own game: its book and its elements
```

`world.md` starts with a YAML header:

```yaml
---
name: Harrowgate
tagline: A harbor town
wiki: wiki
stories: stories
---
```

[docs/world-format.md](docs/world-format.md) describes every file and header field the app reads, including entries, pictures and framing, dates and eras, manuscripts, beats and threads, series, story structures, game engines and elements, and campaigns and sessions.

## Building

- `npm install` installs the frontend dependencies.
- `npm run dev` serves the app in a browser at http://localhost:1420, with two small built-in demo worlds. Harrowgate has a wiki, stories, a campaign, and a game built on a sample engine. Low Tide has no game yet, so starting one can be tried.
- `npm test` runs the unit tests, and `npm run check` type-checks the code. `npm run build` builds the screens, which also proves that the workers and the bundled files are put together correctly.
- `cargo test` in `src-tauri/` runs the Rust tests. On a fresh copy, make an empty `dist` folder at the top first (`mkdir -p dist`), because the app's settings expect one to exist.
- The tests need Node 22.18 or later, which runs TypeScript test files as they are.
- `npx tauri dev` runs the desktop app. It needs Rust and, on Linux, the WebKitGTK development libraries.
- `npx tauri build` builds an installer for the current platform. Release builds sign their update files, so a local build needs the update key in `TAURI_SIGNING_PRIVATE_KEY`, or `--config '{"bundle":{"createUpdaterArtifacts":false}}'` to skip signing.

## Releases

GitHub Actions builds the macOS and Windows apps on every push to `main` and publishes each build as a release. A release is numbered 1.0 and the number of its build, such as 1.0.148. The unit tests and the type check run first, and a build that fails them is never made. A push that changes only markdown files builds nothing. The Rust tests run in a workflow of their own, when the Rust side changes, and do not hold a release back. Updates are signed with the project's update key, and the app refuses any update that is not signed with it. The builds are not yet code-signed with Apple or Microsoft certificates, so macOS and Windows show a warning the first time the app is installed by hand.

## Stack

Tauri 2 with a Rust backend, Svelte 5 and TypeScript for the screens, CodeMirror 6 for the editor, PDF.js for rulebooks, Dice-Box for the dice, nspell with the dictionary-en and dictionary-es-mx word lists for spelling, and Vite. Fonts are bundled, so every theme works offline.
